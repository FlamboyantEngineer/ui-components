# Labs

Every component has a static lab page that renders its full variant, size and state matrix. Labs are debugging and review pages, not package API, but hosts may serve the built labs from the package.

## UIC-LABS-1 - Pages

### UIC-LABS-1.1 - Static files

Each lab shall be a static file `labs/<name>.html` that loads a prebuilt bundle from `labs/build/<name>.js`. `npm run build:labs` builds every bundle, and the labs need nothing beyond a static file server (`npm run labs` is one). `labs/index.html` lists every lab by group with its description.

Implementation: `scripts/build-labs.mjs`, `scripts/serve-labs.mjs`, `scripts/lib/labs.mjs`, `scripts/check-labs.mjs`
Verification: `e2e/lab-harness.spec.ts`

### UIC-LABS-1.2 - Shipped in the package

The published package shall contain the lab pages, `labs/reference.css` and the built bundles, so a host can serve them without building this repository.

Implementation: `package.json`, `scripts/check-package.mjs`
Verification: `test/package.test.ts`

## UIC-LABS-2 - Chrome

### UIC-LABS-2.1 - Stylesheet picker

Every lab and the index shall show a toolbar with a stylesheet picker offering Unstyled, Reference (`labs/reference.css`) and Custom URL. The chosen stylesheet applies to the lab content immediately. The root element reports the stylesheet's loading state in `data-lab-stylesheet-state` (`none`, `loading`, `loaded`, `error`).

Implementation: `labs/src/chrome/lab-chrome.tsx`, `labs/src/chrome/settings.ts`, `labs/src/chrome/mount.tsx`
Verification: `e2e/lab-harness.spec.ts`, `labs/src/chrome/settings.test.ts`

### UIC-LABS-2.2 - Theme attribute

The toolbar shall offer a theme value and the root-element attribute it is written to (`data-theme` by default), so a host stylesheet's own theme switch can be exercised.

Implementation: `labs/src/chrome/lab-chrome.tsx`, `labs/src/chrome/settings.ts`
Verification: `e2e/lab-harness.spec.ts`, `labs/src/chrome/settings.test.ts`

### UIC-LABS-2.3 - Query string and remembered choice

`?stylesheet=` (`none`, `reference` or a URL), `?theme=` and `?themeAttribute=` shall preselect the settings. Otherwise the last choice made in the toolbar applies, remembered in `localStorage`; a browser that refuses storage falls back to the defaults (reference sheet, no theme). Changing a setting rewrites the query string, and the index carries the current settings into every lab link.

Implementation: `labs/src/chrome/settings.ts`, `labs/src/chrome/mount.tsx`
Verification: `e2e/lab-harness.spec.ts`, `labs/src/chrome/settings.test.ts`

### UIC-LABS-2.4 - Isolated chrome

The toolbar shall render in a shadow root with its own styles, so neither the chosen stylesheet nor the lab content changes how it looks.

Implementation: `labs/src/chrome/mount.tsx`, `labs/src/chrome/lab-chrome.tsx`
Verification: `e2e/lab-harness.spec.ts`

## UIC-LABS-3 - Content

### UIC-LABS-3.1 - Reference stylesheet

`labs/reference.css` shall be a plain, neutral and readable stylesheet that styles only hook classes and data attributes plus the document base, with a dark theme under `data-theme="dark"`. It styles every root and slot hook any spec declares. It imports `labs/reference/base.css` and one partial per spec (`labs/reference/<spec>.css`), and its import list is generated by `npm run new:lab -- --sync`.

Implementation: `labs/reference.css`, `labs/reference/base.css`, `scripts/lib/labs.mjs`, `scripts/check-specs.mjs`, `scripts/check-labs.mjs`
Verification: `e2e/lab-harness.spec.ts`

### UIC-LABS-3.2 - State matrix

`StateMatrix` shall render every combination of a lab's axes in one table, the last axis as columns, with each cell addressable as `data-lab-cell="axis=value …"` for browser tests and screenshot comparison. The table stays readable unstyled.

Implementation: `labs/src/chrome/state-matrix.tsx`
Verification: `e2e/lab-harness.spec.ts`

### UIC-LABS-3.3 - Browser fixture

The Playwright fixture `lab` shall open a lab with a given stylesheet and theme, wait until it has rendered and its stylesheet has loaded, fail the test on any page or console error, and run axe on the lab content.

Implementation: `e2e/fixtures.ts`
Verification: `e2e/lab-harness.spec.ts`

### UIC-LABS-3.4 - Accessible in both themes

Every lab shall pass axe with the reference stylesheet in its light theme and in `?theme=dark`, so a lab never ships a state that assistive technology cannot reach and the reference palette keeps its contrast in both themes.

Implementation: `labs/reference/base.css`
Verification: `e2e/accessibility.spec.ts`
